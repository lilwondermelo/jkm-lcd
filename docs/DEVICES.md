# Другие модели кулеров

Сейчас проект настроен на **одну** модель: USB `1a86:5722`, кадр 13 байт,
9600 8N1. Это не универсальный драйвер: у других индикаторов другой USB-ID,
скорость, длина и смысл байтов. Автоматически «найти любой кулер» программа
не может.

## Что можно настроить без кода

Переменные окружения сервера (или `Environment=` в systemd-юните):

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `JKM_TTY` | — | явный путь, например `/dev/ttyUSB0` |
| `JKM_VID` | `1a86` | USB Vendor ID |
| `JKM_PID` | `5722` | USB Product ID |
| `JKM_BAUD` | `9600` | скорость порта |

Пример:

```bash
sudo systemctl edit jkm-lcd
# [Service]
# Environment=JKM_VID=1a86 JKM_PID=7523 JKM_BAUD=115200
sudo systemctl restart jkm-lcd
```

Порт ищется по VID/PID среди `/dev/ttyACM*` и `/dev/ttyUSB*`; если задан
`JKM_TTY`, используется он. Поэтому на другой материнской плате с другим
USB-портом ничего настраивать не нужно: тот же кулер имеет тот же VID/PID,
а имя порта (`ttyACM0`, `ttyACM1`, `ttyUSB0`…) значения не имеет.

Если сервер запускается не от root, пользователь должен иметь доступ к порту
(группа `dialout` на большинстве дистрибутивов, `uucp` на Arch). Для
стабильного имени есть правило `packaging/udev/90-jkm-lcd.rules` —
после установки порт доступен как `/dev/jkm-lcd`.

## Если протокол другой

Нужен отдельный «профиль»: своя длина кадра, флаги, handshake. За основу
берите `server/display.py` (порт/handshake) и `server/animations.py`
(что и куда писать). Добавьте профиль и выбор по VID/PID — это отдельная
работа, но структура проекта к этому готова.

## Как узнать параметры своего устройства

```bash
lsusb
sudo dmesg | grep -i tty
python3 - <<'PY'
import glob, os
for p in glob.glob('/dev/ttyACM*') + glob.glob('/dev/ttyUSB*'):
    print(p)
PY
```

Если `lsusb` показывает `1a86:5722` — скорее всего подойдёт как есть.
Если другой ID — настройте `JKM_VID/JKM_PID` и проверьте кадры через
`/debug.html` (страница «протокол»).
